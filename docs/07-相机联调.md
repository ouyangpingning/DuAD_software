# 07 相机联调

## 架构

```
QML (CameraPage / DetectPage)
   │  context property
   ▼
CameraBridge (backend/Src/camera_bridge.py)   ← QML 相机桥
   │
   ▼
CameraDevice / CameraManager (backend/Src/camera.py)
   │
   ▼
gxipy (backend/gxipy/)                        ← 大恒 SDK Python wrapper
   │  ctypes 调用
   ▼
libgxiapi.so + 依赖 (backend/libs/)           ← 大恒动态库
```

## CameraBridge 接口（QML 可调用）

| 接口 | 类型 | 说明 |
|---|---|---|
| `search()` | Slot | 枚举设备 → 信号 `camerasFound([{model, sn}])` |
| `connectCamera(sn)` | Slot | 打开相机 → `cameraOpened` / `cameraError(msg)` |
| `disconnectCamera()` | Slot | 关闭 → `cameraClosed` |
| `getFeature(name)` | Slot→float | 读特征（数值），失败返回 -1 |
| `setFeature(name, value)` | Slot | 写特征（bool 传 0/1，内部转字符串） |
| `startGather()/stopGather()` | Slot→bool | 采集原语（由 main.py 采集仲裁方驱动；启动前切 Continuous + 帧率控制 On） |
| `applyRoi(x,y,w,h)` / `resetRoi()` | Slot | 归一化 ROI → GX 参数（宽 8/高 2 步进对齐，先 OFFSET 后 WIDTH/HEIGHT） |
| `frameReady(QImage)` | Signal | 采集帧（numpy→QImage，兼容信号） |
| `rawFrameReady(np.ndarray)` | Signal | 采集帧 numpy RGB（RealtimeDetectBridge 消费） |
| `frameIndex` / `imageWidth` / `imageHeight` / `gathering` | Property | QML 实时取图与窗口比例 |
| `cameraConnected` | Property | 连接状态（同步到 AppBridge） |

QML 侧接线模式（CameraPage 的 Component.onCompleted）：
```qml
Component.onCompleted: {
    CameraBridge.camerasFound.connect(function(cams) {
        _hasCamera = cams.length > 0
        _cameraName = cams[0].model
        _serialNumber = cams[0].sn
    })
    CameraBridge.cameraOpened.connect(function() {
        _connecting = false
        _cameraConnected = true
        settingsPanel.initFromCamera()   // 读回参数初始化面板
    })
    CameraBridge.cameraError.connect(function(msg) { _connecting = false })
}
```

## 特征读写

特征名 → 类型推断（gxipy 命名前缀）：
```python
def _feature_type(name):
    if name.startswith("GX_STRING_"):  return "string"
    if name.startswith("GX_INT_"):     return "int"
    if name.startswith("GX_FLOAT_"):   return "float"
    if name.startswith("GX_BOOL_"):    return "bool"
    if name.startswith("GX_COMMAND_"): return "command"
    return "enum"
```

常用特征（大恒标准）：
| 特征 | 说明 |
|---|---|
| `GX_FLOAT_EXPOSURE_TIME` | 曝光时间（**微秒 μs**） |
| `GX_FLOAT_GAIN` | 增益 dB |
| `GX_FLOAT_ACQUISITION_FRAME_RATE` | 目标帧率 |
| `GX_FLOAT_CURRENT_ACQUISITION_FRAME_RATE` | 当前帧率（只读） |
| `GX_ENUM_DEVICE_LINK_THROUGHPUT_LIMIT_MODE` | 链路吞吐量限制开关（0=Off，1=On；采集前由代码写 Off） |
| `GX_INT_DEVICE_LINK_THROUGHPUT_LIMIT` | 链路吞吐量限制值（B/s，默认 36,000,000 时 5MP 卡 7.2fps） |
| `GX_ENUM_ACQUISITION_MODE` | 0=SingleFrame 2=Continuous |
| `GX_BOOL_GAMMA_ENABLE` / `GX_ENUM_GAMMA_MODE`（0=SRGB 1=User） / `GX_FLOAT_GAMMA_PARAM` | Gamma |
| `GX_INT_WIDTH/HEIGHT/OFFSET_X/Y` | 分辨率与裁剪 |

**坑**：
- bool 特征写入底层要求字符串 `"true"/"false"`（camera.py 的约定），CameraBridge 内部转换。
- `GX_FLOAT_GAMMA_PARAM` 在 MER2 固件**只读**（写返回 -8 INVALID_ACCESS），界面只读显示。
- 写分辨率要先设 OFFSET 再设 WIDTH/HEIGHT（否则越界报错）；步进对齐宽 8 高 2。
- **Bayer 转换按帧内 `pixel_format` 动态选 RG/GB/GR/BG**，写死 BG 会导致黄/蓝互换。
- **低帧率先看曝光时间**：实测曝光 165508us 时无论目标帧率写多少，实际只能
  `1e6/165508≈6.04fps`。`gather_start` 会自动把曝光压到 `1e6/target_fps*0.9`。
- **其次才是 `DeviceLinkThroughputLimit`**：`gather_start` 会先写
  `GX_ENUM_DEVICE_LINK_THROUGHPUT_LIMIT_MODE = 0`（Off）。若仍低帧率，
  用 `lsusb -t` 确认相机挂在 5000M SuperSpeed 上（480M 是 USB2）。

## 三个环境级大坑（部署必读）

### 1. LD_LIBRARY_PATH 必须在进程启动时注入
glibc 的 dlopen 依赖解析**只认进程启动时的 ld 搜索路径**，运行时设置无效。
main.py 启动时检测并**自动重启进程**注入：
```python
if <backend/libs 存在> and <LD_LIBRARY_PATH 未包含>:
    os.environ["LD_LIBRARY_PATH"] = libs
    os.execv(sys.executable, [sys.executable, "-u"] + sys.argv)  # -u 防日志缓冲丢失
```

### 2. GenICam 传输层（.cti）必须齐全
缺 `GxU3VTL.cti` 等传输层文件时：`gx_init_lib` 返回 **-1**、枚举永远 0 台
（即使相机在 lsusb 可见、udev 权限正确）。官方安装脚本会把 .cti 装到 /usr/lib，
本项目放在 backend/libs/ 里。

### 3. USB 权限（udev 规则）
普通用户无权限访问相机设备 → 枚举不到。需要 root 安装规则：
```bash
sudo cp backend/config/99-galaxy-dev.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
# 重新插拔相机
```
规则内容：`SUBSYSTEM=="usb", ATTRS{idVendor}=="2ba2", MODE:="0666"`（2ba2 是大恒 VID）。

## 诊断方法论

相机问题按层排查（本项目实战流程）：
1. `lsusb` —— 系统层：相机有没有被识别
2. `ls -l /dev/bus/usb/*/*` —— 权限层：是不是 0666
3. 底层调 `gx_init_lib()` / `gx_update_device_list()` —— SDK 层：看 status 码
   - `-1` 内部错误（多半 .cti 缺失）
   - `-13` 未初始化（init 失败的连锁）
   - `-8` INVALID_ACCESS（固件只读特征）
4. 桥层打印 —— CameraBridge 的日志

## 帧数据流（Detect 实时联调，已实现）

```python
# CameraDevice 采集回调（camera.py）
def capture_image(self, frame_param_ptr):
    # 大恒帧 → numpy RGB
    numpy_img = numpy.frombuffer(output_buffer, dtype=numpy.uint8).reshape(h, w, 3)
    self.image_captured.emit(numpy_img)

# CameraBridge：写 provider + 通知 QML + 发给实时推理管线
def _onFrame(self, numpy_img):
    h, w, _ = numpy_img.shape
    qimg = QImage(numpy_img.data, w, h, w * 3, QImage.Format_RGB888).copy()
    self.frameProvider.set_frame("original", qimg)
    self._frameIndex += 1
    self.frameIndexChanged.emit()      # QML 重新请求 image://camera/original?t=<index>
    self.rawFrameReady.emit(numpy_img) # RealtimeDetectBridge 后台推理
```

QML 侧实时画面：
```qml
// 原图
source: "image://camera/original?t=" + CameraBridge.frameIndex
// 热力图（DetectBridge.resultCounter 每次新推理结果自增）
source: "image://camera/heatmap?t=" + DetectBridge.resultCounter
// 缺陷定位图
source: "image://camera/mask?t=" + DetectBridge.maskCounter
```

`main.py` 的采集仲裁：`AppBridge.collectingOwner == "detect"` 时执行
`CameraBridge.startGather()` + `DetectBridge.start()`；owner 变为其他值/相机断开时
执行 `DetectBridge.stop()` + `CameraBridge.stopGather()`。算法开关由
`AppBridge.algorithmEnabledChanged` 同步到 `DetectBridge.set_algorithm_enabled`。
