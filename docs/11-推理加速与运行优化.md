# 11 推理加速与运行优化

> 本文记录上位机推理性能从 **960ms → 108ms（约 9 倍）** 的完整过程：
> CPU → GPU → TensorRT，以及过程中的硬件教训（fp16 陷阱）、内存优化和
> 一个对话框修复。核心知识点：**TensorRT 是什么、为什么快、怎么配置**。

## 性能演进时间线

| 阶段 | 端到端耗时 | 关键改动 |
|---|---|---|
| 初始（CPU 推理） | ~960ms | onnxruntime CPU 版，模型跑在 i5-10400 |
| GPU（CUDA EP） | ~330ms | 装 onnxruntime-gpu + CUDA 库，走 GTX 1650 Ti |
| **TensorRT** | **~108ms** | 装 TensorRT 10，provider 优先 TRT（69ms 推理） |

## 第一阶段：CPU → GPU

### 环境现状

机器有 GTX 1650 Ti（4GB），但 venv 里是 onnxruntime CPU 版
（`get_available_providers()` 只有 CPU）——119MB 的 DINOv2 fp32 在 6 核
CPU 上单次 ~900ms 属正常。

### 改动

1. 装 `onnxruntime-gpu`（替换 CPU 版）+ `nvidia-cuda-runtime/cublas/curand/cudnn-cu13`
   （CUDA 13 运行时库 pip 包，~4GB）
2. **LD_LIBRARY_PATH 注入**：nvidia 库在 `site-packages/nvidia/*/lib`，
   dlopen 依赖解析只认**进程启动时**的 ld 路径（运行时设置无效）——
   `activate` 脚本和 `main.py` 自重启注入段都要加
3. **venv 自检**（容易踩坑）：系统 `/usr/bin/python3` 也装了 PySide6 +
   onnxruntime CPU 版！直接 `python3 main.py` 能跑但永远走 CPU。main.py
   启动时检测解释器，非 venv 自动 `execv` 切到 `pyqml/bin/python` 重启

```python
# main.py 顶部（任何 onnxruntime import 之前）
if sys.prefix != str(_VENV_DIR):
    os.execv(str(_VENV_DIR / "bin" / "python"), [..., "-u"] + sys.argv)
```

## 第二阶段：TensorRT（重点）

### TensorRT 是什么

NVIDIA 的**推理引擎**（Inference Engine），不是推理框架（PyTorch/ONNX
Runtime 才是框架）。它把 ONNX 图编译成 GPU 专属的**优化引擎**：

- **算子融合**：把多个小算子合并成一个大 kernel（如 attention 的
  QK^T→Softmax→AV 融合成一个 fused kernel），减少 kernel launch 和
  中间显存读写
- **自动调优**：同一算子试多种 kernel 实现，选最快
- **图级优化**：死代码消除、常量折叠、内存复用

> 类比：ONNX Runtime 像"通用编译器"（每个算子一个 kernel，按图依次执行）；
> TensorRT 像"专属编译器"（把整段图编译成高度优化的机器码，还帮你做
> 内联）。对 Transformer 类模型（如 DINOv2 的 ViT）收益尤其明显。

### 硬件教训：GTX 1650 Ti 的 fp16 陷阱

探索过程中先试了 fp16 模型（权重减半、理论带宽减半）——**反而慢了
0.6x**！原因：**GTX 1650 Ti（TU117）是"阉割版"Turing**，fp16 计算单元
被砍掉（fp16 走 1/64 慢速路径）。**只有 RTX 系列（TU10x）才有 2:1 的
fp16 加速**。教训：买卡/优化前先查硬件规格，别被"Turing 支持 fp16"的
宣传误导。

CUDA Graph（省 kernel launch 开销）也试了——0.22x 更慢（capture 开销
大于收益）。**TensorRT 是这台卡上唯一的大收益方案**。

### 落地配置（onnx_infer.py）

```python
providers = [p for p in ('TensorrtExecutionProvider', 'CUDAExecutionProvider',
                         'CPUExecutionProvider')
             if p in ort.get_available_providers()]
```

- **版本匹配**：ORT 1.28 要 `libnvinfer.so.10`（TRT 10.x），装
  `tensorrt_cu13_libs==10.16.1.11`（pip 只有 11.x 的 `tensorrt` 主包，
  需单独指定 libs 包版本）
- **库路径**：TRT 库在 `site-packages/tensorrt_libs/`，同样注入
  LD_LIBRARY_PATH
- **provider_options 必须最简** `{"device_id": 0}`——带
  `trt_engine_cache_*` / `trt_max_workspace_size` 选项会让
  ORT 1.28 + TRT 10.16 **静默加载失败回退 CPU**（本次踩坑）
- **首次引擎构建 ~17s**（一次性）：由启动预热（warmup 后台线程）完成，
  用户无感；切换模型时同样后台重建。无磁盘缓存（cache 选项被上面
  的 bug 挡住），每次启动构建一次，可接受

### 实测结果

| provider | 推理耗时 | 说明 |
|---|---|---|
| CPU | ~960ms | 基线 |
| CUDA | 283ms | fp32 |
| **TensorRT** | **69ms（4.1x）** | 算子融合，分数与 CUDA 完全一致 |

判断是否生效：启动日志 `模型预热完成（['TensorrtExecutionProvider', ...]）`。

## 内存诊断与优化

上位机 RSS 1.64GB，构成（逐阶段测量）：

| 来源 | 内存 | 能否减 |
|---|---|---|
| onnx 模型图 + 权重（CPU 侧） | ~200MB | fp16 可减半（但本卡 fp16 慢） |
| **CUDA context（cuBLAS/cuDNN 初始化）** | ~340MB | 用 GPU 的固有成本 |
| 首次推理缓冲（pinned memory 等） | ~357MB | 无泄漏，封顶 |
| QML 界面层（6 页面场景树） | ~700MB | Loader 懒加载可减半 |

已落地：`gpu_mem_limit=3GB`（防显存 arena 膨胀——4GB 卡上曾膨胀到
3.7GB，其他进程开 CUDA session 直接 OOM）。实测 `ORT_ENABLE_BASIC` 和
`enable_mem_pattern=False` **无内存收益**（大头不是图优化副本），保留
仅为无副作用。

## 对话框修复：为什么文件浏览器"长得丑"

现象：打开图片时是"银白、大字体、每行带 size"的老式对话框，而不是
现代 GTK 样式；且不同终端启动表现不一致。

```
根因：QGuiApplication 未设置 desktopFileName
  → Qt 无法在 portal registry 注册应用
  → QML FileDialog 走不了 XDG Desktop Portal（系统原生对话框）
  → 回退 Qt 自绘对话框（就是那个丑的）
```

修复（main.py）：

```python
app.setDesktopFileName("duad-software")
# 并自动安装 ~/.local/share/applications/duad-software.desktop
# （portal 要求 app ID 有对应 .desktop 文件，Exec 用 sys.executable 动态生成）
```

验证：日志从 `Unable to register application with portal registry` →
`Successfully registered with host portal as "duad-software"`。

## 关键点总结

1. **先确认硬件再选优化路线**——1650 Ti 的 fp16 是阉割的，fp16 模型
   反而慢；TensorRT 的算子融合对 fp32 也有效，是通用大杀器。
2. **TensorRT = 图编译**：融合 kernel + 自动调优，对 Transformer 收益
   最大（69ms vs 283ms）；provider 顺序 TRT → CUDA → CPU 自动回退。
3. **环境坑**：onnxruntime-gpu 的 CUDA/TRT 库都要在进程启动前注入
   LD_LIBRARY_PATH；系统 python3 也有全套 CPU 依赖，main.py 用 venv
   自检强制切换。
4. **显存是资源**：4GB 卡上必须设 gpu_mem_limit 防 arena 膨胀。
5. **原生对话框依赖 portal**：desktopFileName + .desktop 文件缺一不可，
   否则 Qt 静默回退自绘。
