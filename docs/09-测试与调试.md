## 关键经验（每个都是踩过的）

1. **必须 `python -u`**：管道下 stdout 全缓冲会吞掉日志，看起来"什么都没发生"。
2. **QML 的 console.log 在测试环境不可见**（输出到 stderr 且被吞）——断言必须靠 Python 读 property，不要指望看日志。
3. **FakeBridge 必须保持引用**：`bridge = FakeBridge()` 存变量，否则 GC 后 QML 侧变 null——点击回调静默失败（界面上就是"点了没反应"）。
4. **控件 className 不是 C++ 名**：Qt 6.11 控件是 QML 实现（`Button_QMLTYPE_*`），匹配用 `"Button" in className`；QQuickButton 这种 C++ 名不存在。
5. **StackLayout 非当前页仍实例化**：切页用 `stack.setProperty("currentIndex", n)`，等布局完成再点（坐标经 mapToScene 换算）。
6. **模态对话框会挡住点击**：测试里 FakeBridge.shouldShowHelp 返回 False，避免说明页弹出遮罩。
7. **时序敏感用 `wait()` 而不是 sleep**：QEventLoop 驱动 QML 动画/Timer 更真实。
8. **QColor 对象比较**：`QColor == "#rrggbb"` 可以；`str(QColor)` 返回的是 repr 形式（不是 "#rrggbb"），别用字符串比较。

## 常见调试技巧

- **启动看 QML 错误**：`python -u main.py` 会打印 `[QML ERROR] ...`（engine.warnings 钩子）。
- **定位"点了没反应"**：① 确认 Python 对象有引用（GC）② 确认信号连接了（Component.onCompleted）③ 看 QML 警告。
- **真机 vs 模拟**：`tests/` 里既有 mock 相机脚本（CI 可用），也有真机脚本（diag_*、repro_*，需要相机插入）。
- **/tmp 会被系统清理**：测试脚本放 `tests/`（项目内），不要放 /tmp。

## 排错速查表

| 现象 | 原因 |
|---|---|
| 下拉框空白（KDE） | Breeze 样式冲突 → 已强制 Fusion；或 popup 高度死循环 → 已同步计算 |
| 相机搜索 0 台 | ① LD_LIBRARY_PATH ② .cti 缺失（init -1）③ udev 权限 |
| 点了没反应 | AppBridge/CameraBridge 被 GC（Python 引用丢失） |
| 滑块参数锁定无效 | SliderRow control 声明了 shadow enabled（已修复，勿回退） |
| 语言切换后 ComboBox 乱 | model 用了翻译文本而非稳定 key |
