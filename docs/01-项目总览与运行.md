## 启动流程（main.py 里发生了什么）

```
main.py 执行顺序：
1. 注入 LD_LIBRARY_PATH（backend/libs）→ 缺则自动重启进程
   —— glibc 的 dlopen 只认进程启动时的 ld 路径，运行时设置无效
2. 设置 QT_QUICK_CONTROLS_STYLE=Fusion
   —— KDE 桌面注入的 Breeze 样式与 Qt 6.11 QML 化控件不兼容（下拉框空白）
3. 创建 QGuiApplication（Qt 应用对象）
3.1 设置应用名 + 窗口图标，并安装 Linux 启动器条目（.desktop + hicolor 图标）
   —— “启动器图标”与“任务栏图标”是两套机制，下面单独说明
4. 注册全局字体（wqy-microhei.ttc）
5. 创建 QQmlApplicationEngine + 设置 QML 导入路径
6. 创建 AppBridge（语言/跨页状态）→ 注册为 QML 上下文属性
7. 创建 CameraBridge（相机桥）→ 注册为 QML 上下文属性
8. 加载 App.qml（QML 侧入口）
```

## 应用图标（Linux 启动器 / 任务栏）

图标源文件是 `DuAD_SoftwareContent/images/duad-software.png`（256×256，
由 Windows 用的 `favicon.ico` 导出，保证两端同一套视觉）。

两条显示路径**必须同时满足**：

| 场景 | 机制 | 代码/文件 |
|---|---|---|
| 应用菜单、桌面快捷方式 | `.desktop` 的 `Icon=duad-software` → hicolor 主题里的同名 PNG | `~/.local/share/applications/duad-software.desktop`、`~/.local/share/icons/hicolor/256x256/apps/duad-software.png` |
| 运行中的窗口/任务栏（X11） | `QGuiApplication.setWindowIcon(...)` 写入 `_NET_WM_ICON` | `main.py` 启动时 |
| 运行中的窗口/任务栏（Wayland） | 没有窗口图标协议，合成器按 `app_id` 找 `.desktop` 的 `Icon=` | `setDesktopFileName("duad-software")` + 上面的 `.desktop` |

`main.py` 每次启动都会把图标复制到 hicolor、并把 `.desktop` 内容与期望值比较，
不一致就重写（旧版本生成的文件没有 `Icon=`，靠这一步自愈）。
`bash install-desktop.sh` 做同样的事，适合打包后首次安装。

排查“图标不显示”时按这个顺序看：

1. `~/.local/share/applications/duad-software.desktop` 里有没有 `Icon=duad-software`；
2. `~/.local/share/icons/hicolor/256x256/apps/duad-software.png` 是否存在；
3. 桌面环境缓存没刷新：重新执行 `bash install-desktop.sh`，或注销重登；
4. 只有任务栏图标不对：确认是 X11 还是 Wayland（`echo $XDG_SESSION_TYPE`），
   Wayland 下必须靠 `.desktop` 匹配，光设 `setWindowIcon` 不够。

## 架构分层（MVC 思想）

```
┌─────────────────────────────────────────────────┐
│  QML 层（View + Controller）                     │
│  页面 / 组件 / 对话框 — 只管界面与交互            │
└──────────────┬──────────────────────────────────┘
               │ 通过 context property 调用（Slot/Property/Signal）
┌──────────────▼──────────────────────────────────┐
│  Python 桥层（Bridge）                           │
│  AppBridge（状态中枢）/ CameraBridge（相机）     │
│  把后端能力翻译成 QML 能调用的接口               │
└──────────────┬──────────────────────────────────┘
               │ 直接调用
┌──────────────▼──────────────────────────────────┐
│  后端层（backend/）                              │
│  相机驱动 / 采集管线 / ONNX 推理                 │
└─────────────────────────────────────────────────┘
```

**核心思想**：QML 不直接碰硬件/算法，一切通过 Python 桥中转。桥保持 Python 侧引用（防 GC），QML 里引用失败会"静默失效"（点了没反应），这是最容易踩的坑。

## 知识点

- **QGuiApplication vs QApplication**：QML 应用用 QGuiApplication（无 QWidget 能力），这是为何老项目的 QFileDialog 在新前端不可用、需要自绘目录选择器。
- **context property**：`engine.rootContext().setContextProperty("AppBridge", bridge)` 让 QML 里任何地方能直接访问 `AppBridge.xxx`。
- **Fusion 样式强制**：`os.environ.setdefault("QT_QUICK_CONTROLS_STYLE", "Fusion")` 必须在创建应用前设置（环境变量）。
