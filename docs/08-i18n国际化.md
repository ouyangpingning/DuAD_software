# 08 i18n 国际化

## 机制

- **源文本 = 简体中文**（代码里直接写 `qsTr("相机设置")`）
- 英文（.qm）和繁体（.qm）是编译产物；中文直接用源文本，**不需要 .qm**
- 语言切换：AppBridge.setLanguage(index) 加载对应 .qm 并调用 `engine.retranslate()` 让所有 qsTr 重新求值
- 选择持久化在 `QSettings("DuAD","DuADSoftware")`

```python
LANG_FILES = {
    0: "app_en",       # English → app_en.qm
    1: None,           # 简体中文（源文本，不加载）
    2: "app_zh_TW",    # 繁体 → app_zh_TW.qm
}
```

## 工作流（新增界面文本必做）

```bash
# 1. 提取新字符串到 app_en.ts（从仓库根目录运行）
#    注意：不能扫整个 DuAD_SoftwareContent（pyqml/ venv 的示例 QML 会被扫进来），
#    必须显式列出源路径
LUPDATE=DuAD_SoftwareContent/pyqml/lib/python3.14/site-packages/PySide6/lupdate
LRELEASE=DuAD_SoftwareContent/pyqml/lib/python3.14/site-packages/PySide6/lrelease
"$LUPDATE" -no-obsolete DuAD_SoftwareContent/App.qml DuAD_SoftwareContent/MainuiRoot.qml DuAD_SoftwareContent/MainWindow.ui.qml DuAD_SoftwareContent/pages -ts translations/app_en.ts

# 2. 填充翻译（新字符串必须同时加入 scripts/gen_translations.py 的 EN 和 TW 两个 dict）
python scripts/gen_translations.py

# 3. 编译 .qm
"$LRELEASE" translations/app_en.ts translations/app_zh_TW.ts
```

**坑**：`pyqml/bin/pyside6-lupdate` 等脚本的 shebang 指向项目改名前的旧路径（bad interpreter），
要用 site-packages 里的原生二进制（上面 LUPDATE 变量的路径）。

## gen_translations.py 原理

它不调用 lupdate 的翻译能力，而是维护两个 **中文→译文** 字典（EN 和 TW），
解析 app_en.ts 的 XML，把每个 `<source>` 对应的 `<translation>` 填上：

```python
EN = {
    "相机设置": "Camera Settings",
    "采集": "Acquisition",
    ...
}
TW = {
    "相机设置": "相機設定",
    ...
}
# 填完 EN 后复制一份做 TW 再填（避免互相污染）
```

所以**新增文本 = 两步**：① QML 里写 `qsTr("新文本")`；② 把 `"新文本": "译文"` 加进两个 dict。

## 注意事项

- **ComboRow 的 model 用稳定 key**（不翻译），显示文本走 displayFunc——避免语言切换时 ComboBox 重建导致 currentIndex 重置。
- **固有名词不翻译**：`Gamma`、`𝒟𝓊𝒜𝒟`、`Topic` 保留原文（翻译文件里会标记 unfinished，属预期）。
- **带参数的字符串**：`qsTr("已保存 %1 张").arg(count)`，翻译时 `%1` 保留。
- **动态拼接不要拆**：整句 qsTr，不要 `qsTr("分数") + " " + score`（翻译会错位）。
- 删除无用文本：`-no-obsolete` 标志会在下次 lupdate 时清掉已删除条目的旧翻译。
