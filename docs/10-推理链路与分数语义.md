# 10 推理链路与分数语义

> 本文讲解上位机的测试推理链路：单张图片 → 异常分数 + 热力图，覆盖
> `backend/Src/onnx_infer.py`、`backend/Src/algorithm_bridge.py` 与
> DetectPage 的测试推理区。重点：**分数的正确语义**（今天修了一个让正常图
> 误报异常的 bug）与**阈值的标定方法**。

## 架构

```
QML (DetectPage 测试推理区)
   │  AlgorithmBridge.inferImage(path)
   ▼
AlgorithmBridge (backend/Src/algorithm_bridge.py)   ← QML 桥，后台线程
   │  懒加载 ONNXAnomalyDetector（线程内建 session）
   ▼
ONNXAnomalyDetector (backend/Src/onnx_infer.py)
   │  预处理 → session.run → 后处理 → 热力图RGB + 分数
   ▼
bottle_k4_s0_full.onnx   （DuAD 算法导出的 ONNX，119MB fp32）
```

推理全程在**后台线程**执行，不阻塞 UI；结果经信号返回：
`inferenceReady(score, heatmapPath)`，热力图存为临时 PNG 供 QML Image 加载。

## 推理管线（onnx_infer.py 的 predict）

```
输入 numpy RGB [H,W,3] uint8
  │ ① 预处理
  ├─ Resize(518,518) + ImageNet 归一化（mean=0.485/0.456/0.406, std=0.229/0.224/0.225）
  │ ② 推理
  ├─ session.run → heatmaps [B,H,W]（patch 级异常分数）+ image_scores [B]
  │ ③ 后处理
  ├─ 双线性上采样到 518² + 高斯模糊（sigma=4，numpy 自实现——Pillow 12 的
  │   GaussianBlur 不支持 float32 图）
  │ ④ 可视化
  └─ 全局固定尺度归一化 → jet 色带 → RGB 热力图
```

## 分数的正确语义（重点）

模型里 `image_scores` 不是"概率"，而是**判别器负输出的 patch max**：

- 训练时判别器把**正常 patch 的输出拉向 ≥1**，异常 patch 的输出拉向 <0
- 导出时 `image_scores = heatmaps.max()`（export_onnx.py:153，与训练侧 DuAD.py 一致）
- 因此：**正常图分数 ≈ -1~1.5，异常图分数 > 2**，带符号、无界、未归一化

### 曾经的 Bug：min-max 归一化导致正常图恒判异常

```python
# ❌ 错误写法（已修复）：score 本身就是 patch max，
#   归一化后恒等于 1.0 → 任何图都判异常！
score = (scores[0] - lo) / (hi - lo)

# ✅ 正确写法：直接返回原始分数，与训练/评估同口径
score = float(scores[0])
```

> 直观理解：`scores[0]` 是"整张图最异常的 patch 有多异常"，它和热力图的
> max 是同一个值。用 min-max 归一化相当于"最高分恒为满分"，正常图的
> 噪声峰值也会被拉到满分 → 正常图误报。**归一化只用于热力图颜色映射，
> 绝不用于分数本身**。

实测分布（bottle 验证集，阈值判断的正常/异常间隔）：

| 类别 | 分数范围 | 说明 |
|---|---|---|
| 正常 good（20张） | 0.59 ~ 1.50 | 判别器对正常图的 max 也常 >0（训练不保证 ≤0） |
| 异常 broken_large（20张） | 1.97 ~ 3.38 | 缺陷 patch 分数显著高 |

## 热力图：颜色映射（百分位）与二值化（原始尺度）分离

> ⚠ 本节以 `DEPLOY_CONTRACT.md`（服务端契约）为准，代码已对齐。

**两个独立操作，顺序不能颠倒：**

```python
# ① 二值化（异常区域定位）：用原始 hm_smooth 与 pixel_threshold 比较，
#    必须发生在任何归一化之前 —— 归一化空间里的固定阈值跨图不可比
anomaly_mask = hm_smooth > pixel_threshold          # 原始尺度

# ② 颜色映射（仅显示）：百分位归一化 p2/p98（逐图自适应）
p2, p98 = np.percentile(hm_smooth, 2), np.percentile(hm_smooth, 98)
norm = np.clip((hm_smooth - p2) / (p98 - p2), 0.0, 1.0)
heatmap_rgb = jet(norm)
```

- **为什么颜色用百分位**：p2/p98 clip 排除了 2% 极端噪声，比纯 min-max 鲁棒，
  换类别模型也无需手动调尺度；`predict()` 的 `vmin/vmax` 参数仍可显式传固定尺度。
- **为什么二值化不能用归一化后值**：每张图 [0,1] 空间不同（p2/p98 逐图变），
  归一化后固定阈值跨图不可比，`duad.pixel_threshold` 在归一化空间无意义。
- `pixel_threshold` 未标定（`duad.pixel_f1_max == -1`）时，定位退化为手动阈值。

## 阈值标定（训练期标定 + calibrate_threshold.py 兜底）

> ⚠ 阈值现在**训练时就地标定**（图像级 youden + 像素级 F1-max），随 ckpt →
> ONNX metadata 走，详见 `docs/12` 与 `DEPLOY_CONTRACT.md`。本节描述的
> `calibrate_threshold.py` 仍保留，作为旧模型/工厂只有好品的兜底标定工具，
> 且与训练期共用同一套 `threshold_utils.py` 口径。

```
用法（在算法仓库 https://github.com/ouyangpingning/DuAD 中执行）：
python deploy/calibrate_threshold.py <model.onnx> \
        --data <mvtec根> --category bottle [--normal-only]
产出：<model>.onnx.threshold.json（上位机启动/切模型时自动读取）
```

- **方法 1（有缺陷标注）**：网格搜索 2000 个阈值，输出
  `youden`（TPR−FPR 最大）/ `best_f1` / `target_fpr`（默认 FPR≤1% 时 TPR 最大）
- **方法 2（工厂只有好品）**：正常样本的 `p99` / `p99.5` 分位（误报率 ≈1%/0.5%）
- `recommended` = 有异常样本取 youden，否则取 p99

bottle 标定结果：正常 0.59~1.54 / 异常 1.15~4.86，**推荐阈值 1.536**
（回测：正常误报 0%、异常检出 96.8%，优于之前拍脑袋的 1.7）。

## 模型切换（选择模型）

- DetectPage"选择模型"按钮 → FileDialog（过滤 *.onnx）→ `AlgorithmBridge.loadModel(path)`
- **关键 bug 已修复**：`loadModel` 必须丢弃旧 session，否则懒加载不会重建，
  切换类别后推理仍走旧模型（静默错误）：

```python
# ❌ 只改路径：_detector 非 None 时永远用旧模型
self._model_path = path

# ✅ 路径变化时置空 + 重新预热（后台，新模型首次推理不卡）
with self._lock:
    self._model_path = path
    self._detector = None
self._load_threshold_from_json()   # 新模型可能带自己的标定阈值
self.warmup()
```

- 阈值联动：阈值读取优先级 **ONNX metadata（训练时标定写入）> `<模型名>.onnx.threshold.json` > 默认 1.7**；
  切换模型自动加载对应阈值，不残留旧模型的值（详见 DEPLOY_CONTRACT.md / docs/12）

## DetectPage 测试推理区（QML 侧）

```

[打开图片] → imagePicker(FileDialog, *.png/.jpg) → _testImagePath

```

## 关键点总结

1. **分数不归一化**——`image_scores` 是判别器负输出的 patch max，带符号无界；
   min-max 归一化会让分数恒为 1，正常图误报。
2. **颜色映射与二值化分离**——颜色用百分位归一化（p2/p98，仅显示）；像素级
   定位用原始 `hm_smooth > pixel_threshold`，必须在归一化之前（契约 3.2/3.3）。
3. **阈值训练期标定、随模型走**——图像级 youden + 像素级 F1-max 阈值在训练时
   算出写进 ckpt → 导出写 ONNX metadata；客户端读取优先级 metadata > JSON > 默认。
4. **换模型要重建 session**——懒加载的坑：路径变了但 session 还在，静默
   用旧模型推理。

## DetectPage 实时推理链路（已联调）

```
CameraDevice.image_captured(np RGB)
  → CameraBridge.rawFrameReady(np RGB)
  → RealtimeDetectBridge（maxsize=1 最新帧队列）
  → AlgorithmBridge.predict_frame()   # 后台线程，复用测试推理同一 ONNX session
  → heatmap/mask ndarray → CameraFrameProvider
  → DetectBridge.resultCounter/maskCounter 信号 → QML Image 重取
```

- `predict_frame` 与单图 `inferImage` 使用同一套阈值/尺度/像素定位参数；
  `_infer_lock` 串行化 session.run，`_build_lock` 防止 warmup 与首帧实时推理
  同时构造两个 session。
- 队列只保留最新帧：模型推理慢于相机帧率时自动丢旧帧，UI 不会被积压帧拖垮。
- 算法开关关闭时实时管线不推理，原图仍以相机帧率直通显示（纯采集模式）。

## 测试推理与实时采集的互斥切换

- 两者互斥，**实时采集优先**：
  - 测试推理进行中点击“开始采集” → 立即切到实时画面；
  - 页面自增 `_testSession` 作废旧测试请求，在途的 `inferenceReady` /
    `maskReady` / `inferenceError` 返回后按 session 号丢弃，不会抢回画面；
  - 实时采集中“选择模型 / 卸载模型 / 打开图片 / 执行推理”均禁用，
    并提示“实时采集中，测试推理已暂停”；
  - 停止采集后才恢复测试推理区。
- 换测试图片同样自增 session，避免上一张图的慢推理结果覆盖新选择。

## ONNX 模型卸载

- `AlgorithmBridge.unloadModel()`：`_detector` 置空、`_model_path` 清空，
  显式 `del old` + `gc.collect()` + `malloc_trim(0)` 释放 session 大块内存；
  阈值/像素阈值/热力图尺度全部恢复默认，并发出 `modelUnloaded`。
- QML 测试推理区新增“卸载模型”按钮（未选模型或实时采集中禁用）。
